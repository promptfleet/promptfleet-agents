## Requirements

- **Rust** toolchain (edition 2024 per workspace `Cargo.toml`).
- **Node.js** 20+ for this documentation site (`docs/`).

## This documentation site

**Always `cd docs` first.** Only `docs/package.json` exists; the repository root is Rust-only. Running `yarn` at the root uses **Yarn 1** (e.g. Homebrew) and can create stray `yarn.lock` / `node_modules` at the root.

```bash
cd docs
corepack enable
yarn install
yarn dev
```

**Yarn version:** `docs/package.json` pins Yarn 4 via `packageManager`. **`corepack enable`** (once per machine) makes the `yarn` shim respect that. Without Corepack, **Yarn 1** may run and fail with **“Ambiguous Syntax Error”** on Berry-only flags.

- **Local:** use `yarn install` (no `--immutable`).
- **CI:** the repo workflow uses `yarn install --immutable` so the lockfile cannot change during the build.

### Troubleshooting Yarn 4 (“Unknown Syntax” / “Ambiguous Syntax” / `While running --non-interactive …`)

Yarn 4 builds its CLI with **Clipanion**. If the **first** token after `yarn` is a **global** `--non-interactive`, many subcommands break — for example **`yarn --non-interactive -v`** and **`yarn --non-interactive install`** fail (reproducible on Yarn 4.13.x). The error footer often says `While running --non-interactive …`.

That usually means something is **not** running plain `yarn …` — it is injecting **`--non-interactive` before the subcommand**. A **very common** cause is a shell **alias**, e.g. zsh:

```text
yarn: aliased to yarn --non-interactive
```

That makes every `yarn` call become `yarn --non-interactive …`, which breaks Yarn 4’s CLI. **Fix:** remove the alias for this project — `unalias yarn` in the current session, or delete the line from `~/.zshrc` / your dotfiles — then open a new shell. Until then, use **`command yarn …`** (zsh/bash: runs `yarn` without alias) or the real binary, e.g. **`/usr/local/bin/yarn …`**, after `corepack enable`.

**What to try**

1. Inspect how `yarn` is resolved: `type yarn`, `alias yarn`, `which -a yarn` (zsh/bash).
2. Bypass an alias: **`command yarn -v`**, **`command yarn install`**, **`command yarn dev`** (same for `build`).
3. Run the same commands in **Terminal.app** / **iTerm** (outside the IDE) if that profile has no bad alias.
4. Read the pinned toolchain without the version subcommand:  
   `node -p "require('./package.json').packageManager"`  
   (prints e.g. `yarn@4.13.0`).

This repo’s **GitHub Actions** workflow calls **`yarn install --immutable`** with **no** leading global `--non-interactive`; that layout is valid.

Build for production:

```bash
yarn build
```

Output is written to `docs/dist/` (with `base` set for GitHub Pages).
